本技能是**薄壳**，不含实现正文。CLI 唯一权威用法来源：gov-hub 仓库（https://github.com/songzhou/gov-hub ，本地安装见 README）。

> **安装参数（安装者必改：把下面路径改成你本机的实际克隆位置）**
> CLI_PATH = E:\Mytest_plugin\gov-hub\govhub.py
> PYTHON = C:\Users\Administrator\AppData\Local\Programs\Python\Python313\python.exe
> （下文所有命令用这两个值代入；找不到 CLI_PATH 时**禁止**静默放弃——告知用户"gov-hub 未安装或路径失效，请按 README 安装"，然后才回退普通方式。）

## 铁律：不许让用户的问题等一个安装问题

**用户的原始问题优先。**不要为了初始化而推迟答案，也不要把邀请拖到答案最后
（拖到最后实测等于没问：用户早就走了）。

正确节奏：**先做问题需要的检索（1~2 批）→ 立刻把邀请问掉 → 继续作答**。

——两种写法都实测失败过：写在回答**之前**，模型以"打断用户"为由违抗整套流程；
写在回答**之后**，模型查了 18 步才轮到邀请，用户等不到。

## 第 1 步：查声明

**让位条款**：若本工作区已有自己的资产/规则查询协议（如 AGENTS.md 已定义 lookup 工具、
`_registry.yaml` 之类），**以项目自己的协议为准**，本技能整体忽略、不要邀请初始化。

用 glob 检查工作区根目录是否存在 `gov-hub.yaml`：

- **存在** → 走下面「供给」；lookup 报 `[UNDECLARED]` / `[MUTED]` 时按其提示处理（拒绝后永久静默）。
- **不存在** → **不要阻塞**：按项目原有方式把用户的问题答完，然后进第 2 步。

## 第 2 步：邀请时机（未声明区）

**邀请不等到全部答完**——实测等到就太晚了：模型查了 18 步才轮到邀请，用户早已没耐心。

- 预计需要 **≥2 次检索**才能答完 → **第一批检索结果回来后就问**（此刻你最清楚"翻了哪些文件、
  几个没在地图上"，报价最真实）；用户选完你继续作答，答案不受影响；
- 一句话就能答 → 答完再问；
- **必须真的调用 `ask_user_question` 工具**：在正文里写"要不要装"不产生弹窗，等于没问。

提问时带上本次的实际代价与收益，例如：
：「刚才为了回答这个问题，我翻了 6 个文件、读了 4 个——装上地图后这类问题一行直达。要现在装上吗？」

- **启用**（推荐）→ `PYTHON CLI_PATH init --main <工作区>`
  → 立刻把**你已经读过的权威文件**逐条 `add` 登记（这是地图最好的第一批条目，
  因为它们是真实问题挑出来的），再 `check` 一遍确认全绿；然后可问一次是否写进 AGENTS.md（第 3 步）；
- **暂不启用，别再问** → `PYTHON CLI_PATH init --decline`，告知已静默，此后永不再提；
- **这次先不用** → 不写任何文件（下次会话再轻问一次），立刻继续把答案给完。

用户拒绝后**不得再问第二次**，也不得因此减损答案质量。

## 第 3 步：可选——写进 AGENTS.md（只问一次，用户不选就不做）

在用户**已启用**之后才提，用 `ask_user_question` 问一次「要不要把项目地图入口写进 AGENTS.md？」
（比技能路由确定：不依赖模型"想起来"）：
- **本项目** → `PYTHON CLI_PATH attach --root <工作区> --scope project`；
- **我的用户级**（一次注册、所有项目生效；未启用项目自动忽略）→ `--scope user`；
- **不用** → 什么都不做。

`attach` 只写标记块（`<!-- gov-hub:begin -->` … `<!-- gov-hub:end -->`），块外一字节不动、
重复执行不重复追加，`PYTHON CLI_PATH detach --root <工作区> --scope <同上>` 可逐字节还原。
**不得在用户没同意时写 AGENTS.md。**

## 供给（已启用区，动手前先查）

```bash
PYTHON CLI_PATH lookup <关键词或整句问法> --root <工作区>
```
- 命中 → 读列出的权威文件，不蛮力翻文件夹（这一条就是省 token 的全部来源）；
- 问到"上一次会话聊了什么/我们之前讨论过什么"——**项目地图不含对话内容**，只有工作区文件；
  如实告诉用户，不要为回忆对话去翻会话日志或 `.dsh/sessions` 目录。

## 回灌（回答完立即做，不要留到"会话收尾"——实测会忘）

**凡是你靠翻文件找到答案、而该文件不在地图上 → 立刻单命令登记：**

```bash
PYTHON CLI_PATH add <文件相对路径> --root <工作区> \
  --keywords 用户本次的实际问法,主题词1,主题词2 \
  --answers "这条能回答什么问题（一行）"
```
登记会自动机检并同步索引；新增/移动文件同理。只读的临时/生成文件用
`--authority generated`（或不登记）。

**登记粒度**：同一主题下有多份独立资产（如各子端各一份清单）→ **每份一条**，
不要合并成一条"总表"；这样删除/改名会被 `check` 的"路径不在盘"立刻抓住。
**不要在地图里记录数量或统计值**——数量由条目自身现数，写进地图就会随文件变动过期。

## 会话收尾（体检）
`PYTHON CLI_PATH status --root <工作区>` 看四灯；`PYTHON CLI_PATH suggest --root <工作区>`
看路线迹里的高频路线与**覆盖缺口**（问了多次但地图没有的主题）。

## 文案纪律
对用户只说"项目地图"，禁用"治理/登记表/回灌"等内部词；完整口径见仓库 `docs/UX_COPY.md`。
