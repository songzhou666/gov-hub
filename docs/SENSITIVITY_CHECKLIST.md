# 发布前脱敏核对清单

> 每次向公开仓库提交前，对**新增/修改的每个文件**逐项核对。任一项命中即阻断提交。
> 用法：PR 自查时逐条打勾；发布 release 前再全量重查一遍。

## A. 源工作台识别信息（绝对禁止）

- [ ] 无真实项目名、公司名、客户名、门店名
- [ ] 无内网域名 / 网关地址 / IP / 端口（含注释与示例）
- [ ] 无账号、手机号、工号、邮箱（作者联系邮箱除外）
- [ ] 无文件系统路径指向源工作台（如 `E:\AI_TEST`）
- [ ] 无 git 历史/提交者信息泄露（首次 push 前检查 `git log`）

## B. 业务语义（绝对禁止）

- [ ] 无具体业务域词汇（就诊、医保、处方、叫号、收费、分表等）——示例一律用虚构域（如 `仓库/拣货/账期`）
- [ ] 无接口名、表名、错误码、单据类型
- [ ] 无环境词（test/prod 环境、审批流）真实细节

## C. 隐性假设（重点自查）

- [ ] 示例配置里不存在"恰好只在源工作台成立"的默认值（如容器名恰好是 case/result）
- [ ] 文档措辞不带源工作台的内部黑话 / 纪律编号（如"85 号协议"）
- [ ] 注释里无"2026-xx-xx 实测"式源项目决策日志引用
- [ ] 通用层代码为重写实现，与源实现无复制粘贴级相似（抽查 diff）

## D. 提交纪律

- [ ] 本清单本身随仓库公开（透明即纪律）
- [ ] 命中 A/B 任何一项 → 修正后**重跑全文检查**，不只改当前文件
- [ ] 命中 C → 改为参数化或虚构示例
