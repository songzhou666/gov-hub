# gov-hub 架构设计（草案 v0.1）

> 状态：骨架稿。scope 配置文件格式是插件对外的第一接口，**须最先冻结**。

## 0. 设计第一原则

治理系统对用户世界的所有假设，必须是**声明的**，不能是**推断的**。
错误代价越高的决策，越要前置人工确认；错误代价越低的产物，越要标记为可重建。

| 决策 | 错误代价 | 对策 |
|---|---|---|
| 项目范围 | 灾难（索引全错） | 声明制 + 确认关 + scope 指纹失效 |
| 目录命名 | 兼容冲突 | 逻辑/物理分层 + 零假设默认档 + 改名只走提案 |
| 索引/卡片 | 低（可重建） | 一律标 generated，永不作 canonical 引用 |
| 越界引用 | 灾难入口 | 待决队列，不静默扩界 |

## 1. 范围声明协议（Scope Protocol）

### 1.1 scope 配置 `gov-hub.yaml`（格式 v1 —— **已冻结，2026-11-03**）

```yaml
version: 1              # 配置格式版本，只增不改
scope:
  roots:                # 根路径列表（支持多根；相对路径相对本文件所在目录）
    - .
    - ../旁挂资料区
  exclude:              # glob 排除项；默认已隐含 **/.git/** 与 **/node_modules/**
    - "**/archive/**"
layout: loose           # loose | mapped | convention
containers: {}          # mapped/convention 档：记录型容器名映射；loose 档忽略
window_days: 30         # 回灌缺口/活跃度窗口（增量制）
thresholds:
  gap_yellow_max: 5     # 回灌灯：0 绿 / 1~黄 / >此值 红
```

冻结纪律：`version` 字段存在即格式不可 backwards-incompatible 变更；
新增字段必须带默认值且旧配置零改动可读；破坏性变更只能升 version 并保留 v1 读取器。

### 1.2 判定流程（三级）

1. **显式声明**：存在 `gov-hub.yaml` → 直接采用，不再探测；
2. **启发式探测**：无配置时，以标记文件（AGENTS.md / .git / package.json / CLAUDE.md 等）
   产出**候选范围清单**（每个候选附探测依据）；
3. **人工确认关**：呈现候选，用户选定/调整后才写入 `gov-hub.yaml` 并固化。
   配置固化的那一刻起，scope 具有指纹 = hash(roots + exclude + version)。

### 1.3 失效与越界

- 所有扫描产物（索引/卡片/缺口清单）携带 scope 指纹；指纹失配 → 产物标记 `stale`，拒绝作答；
- agent 执行中遇到范围外引用 → 写入 `pending/` 待决队列（纳入 / 映射 / 忽略三选一），
  **绝不静默扩界**；
- 宁可第一天没有资产地图，也不要有一张错误的资产地图。

## 2. 布局适配层（Layout Profiles）

治理的全部判断建立在登记表（逻辑层）之上；目录命名只是物理层的一种可选风格。

| 档位 | 行为 |
|---|---|
| `loose`（默认） | 零假设只读治理：不解析命名、不要求结构，任何目录形态都能跑 |
| `mapped` | 用户在配置中声明容器映射（如 `result 类容器 = [runs, outputs]`），启用容器级活跃度与缺口扫描 |
| `convention` | 在 mapped 基础上，对**新产出**施加命名规范；对存量只出违规清单 |

**改名纪律**：扫描出违规 → 改名提案（含引用影响面 + dry-run diff）→ 用户逐批批准 →
执行后强制回归机检。自动改名在任何情况下不发生。

## 3. 登记表（逻辑层）与机检

- 登记表 schema 参考源实践（entries + keywords + authority 三级 + plan 归属），
  字段以通用语言重写；`authority: canonical | derived | generated` 语义不变；
- 机检最低集：① 登记表 ↔ 磁盘一致性；② 规则/薄壳漂移（凡声明了薄壳结构的 profile）；
  ③ 回灌缺口（见 §4）；④ scope 指纹校验。四条即四盏灯的前身。

## 4. 回灌缺口（增量制）

- 缺口 = 治理容器内**近 N 天**（默认 30，可配）有改动、且主题未命中登记表的单元；
- **不追溯存量**——存量噪音会淹没面板，冷启动期只盯增量；
- 阈值分档：0 绿 / ≤5 黄 / >5 红；每条缺口必须带建议动作（登记 or 归档）。

## 5. 冷启动坡道

1. 安装即体验：内置 `seeds/` 虚构示例工作区，装完 check 全绿、lookup 有结果；
2. 演示缺口：种子区预置 1~2 条可立刻修复的缺口，让用户完成一次回灌闭环；
3. 园丁前置：把"新增必须登记并过机检"做进 agent 协议收尾步骤，纪律由 agent 执行而非用户记忆；
4. 健康度可视化：`status` 命令输出四灯 + 缺口数，让飞轮可感知。
