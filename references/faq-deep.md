# 深水区问答：边缘场景 / 兼容性 / 安全合规

1. **多工作区同时开着，ensure 会不会问好几次？** 每个工作区独立三态。同一会话内对同一区只问一次；
   不同区（比如两个仓库来回切）各问各的，这是设计而非缺陷——每个区的意愿都该被尊重。
2. **`init --decline` 的标记写在哪、会不会污染工作区？** 写在 `<工作区>/gov-hub.yaml` 一个字段里，
   是唯一一个未经确认也会写的文件；内容只有指纹与 declined 标记，删除文件即回到"未声明"状态。
3. **宿主没有 ask_user_question 工具怎么办？** 用宿主的等价提问机制；若完全没有，
   把三选一作为正文最后一个问题直接问，用户答复后按同样三分支处理。
4. **PyYAML 没装会怎样？** 自动降级：登记表仍用 YAML 存（人类可读），检索索引退化为 JSON；
   所有命令不受影响。可选依赖，不强制安装。
5. **Windows / macOS / Linux 都能跑吗？** 纯 Python 标准库，三平台一致；路径全部经 `pathlib` 处理，
   入口块模板按运行机器实际路径渲染。
6. **登记表会不会越来越大、拖慢 lookup？** 索引按需重建且常驻内存查询，几千条目量级毫秒级；
   `status` 会提示 stale 索引。真正的成本约束是"每条一行 answers"，防止登记表变散文。
7. **两个 agent 同时 add 会冲突吗？** `add` 是"读-改-写-机检-回滚"的事务式流程，后写者覆盖前写者
   的可能性存在但机检会抓住结构性损坏；并行写同一工作区属于使用不当，建议串行。
8. **技能文件被安全软件误报/被扫描器标记怎么办？** 本技能无网络、无 eval、无子进程注入，
   全部命令可见于 SKILL.md 与 README；如被标记，核对文件哈希与 GitHub 发布版一致后放行。
9. **企业内网/私有部署能用 SkillHub 或 npm 分发吗？** 都可以绕开：仓库本身就是技能包，
   `git clone` + `python govhub.py install` 即完成，不依赖任何在线市场。
10. **卸载后工作区里残留什么？** `.govhub/` 索引、`gov-hub.yaml`、`registry.yaml` 保留（它们是
    用户数据）；技能目录与 AGENTS.md 入口块由 `uninstall`/`detach` 精确移除。
